# 双臂快递分拣：ACT 技能与连续交接设计

当前说明是设计分析，不表示项目已经实现多模型安全热切换。

## 当前实现的边界

Web 将 `eval` 作为任务启动、停止。`backend/main.py` 根据 `continuous_sort`、`auto_home` 选择官方录制入口或 `safe_record.py`，再用 `REBOT_KEEP_POSE` 控制退出清理。启用自动收工时，结束进程可能触发归零；保持姿态分支也会关闭软件总线和相机租约，不能等同于有持续反馈、重力补偿和看门狗的常驻控制进程。

本地 LeRobot 的异步策略服务器在设置策略时调用 `from_pretrained()` 加载模型，不能直接认为已有多模型缓存和经过验证的交接协议。

## 推荐的技能划分

保留“堆叠分离/推拢”“盒子翻面”“袋子翻面”等独立策略。视觉状态机负责选择技能、确认完成和失败重试，出料优先规则控制。堆叠只在遮挡/高度等证据充分时判断；扫码失败可能是反光、模糊或遮挡，不能直接视为面单朝下。

单一 ACT 可以学习覆盖过的长流程，但普通图像+状态 ACT 不会仅因加入三个摄像头或文字任务描述，就自动获得可靠的任务选择能力。若统一模型，需要覆盖场景分支、失败恢复及动作歧义的数据，并验证条件输入与训练方式；不建议把现有独立技能数据直接混合后期待自动路由。

## 控制进程和策略生命周期

常驻 CAN 控制进程持续读取 14 维实测状态、执行重力前馈和安全限幅、心跳/力矩看门狗；只有它拥有电机连接。策略进程输出候选动作，不直接管理使能、失能和回零。切换模型时不停止 CAN 进程，也不调用其断开清理。

三路相机常驻于唯一视觉采集进程。策略切换时保持相机键、相机顺序、图像预处理和时间戳一致，分别使用各模型的归一化处理器；同时核对关节顺序、单位、方向和左右臂约定。

按实际显存测量结果预加载、预热常用策略，或至少缓存当前与下一策略。预热只做计算，不向电机发送动作。上一模型完成安全交接后保留为缓存对象，不必等待卸载完成再运行下一模型；显存回收走独立管理流程。

## 交接步骤

1. 视觉与实测状态确认上一技能结束。优先选择包裹已获支撑、机械臂已解除危险接触、速度较低的交接点。
2. CAN 进程继续闭环保持；停止接受上一技能的新推理结果，清除其未执行动作队列。
3. 更新策略代号，重置新策略的动作队列、观测历史和适用的时序集成状态。旧代号或过期观测对应的结果不再执行。
4. 用最新的三路画面和实测关节状态运行下一策略，核验首段动作的位移、速度、加速度、关节范围和双臂碰撞风险。
5. 只有入口状态合格才执行。需要过渡时，规划并验证过渡路径；简单关节插值/限速并不等于避障。入口不合格或首段动作超限时保持/恢复到已验证状态，不靠放宽限幅强行接入。

普通换模型不触发失能。真实过载、失联或控制故障的处理仍由安全机制决定，不能为“连续运行”屏蔽看门狗。抓持或抵住包裹时，保持姿态也不一定安全，应先完成有支撑的交接或采用专门的接触控制。

## 数据集和中间姿态

若每集都录成“机械零位→技能→机械零位”，模型可能学习起落和收回动作。异步推理只能帮助计算与执行并行，不会自动删除这些动作，也不会让下一模型适应任意中途姿态。

交接姿态是上一段技能的结束条件、下一段技能的入口条件。它是有允许范围的完整状态（含关节、速度、夹爪、包裹支撑/接触及目标可见性），不是一定相同的固定零位，也不是直接复制上一段最后一帧。

已有数据可标注并裁剪掉纯初始化和收工片段，创建新数据版本且同步保留全部三路相机与动作时间对齐；技能内部必要的接近、接触、脱离和恢复动作不能误删。裁剪不等于获得任意姿态泛化，仍需要采集交接入口及其合理扰动范围内的示教，再分别训练/微调。模型切换还要做独立的闭环交接验证。
