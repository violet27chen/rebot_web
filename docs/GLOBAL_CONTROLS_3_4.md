# 3.4.0 / 20261114.1

## 设备与任务操作

- 双臂类型检测按钮移出折叠区，探测脚本使用当前 LeRobot 的插件注册和 Draccus 公共注册表。检测后可应用真实注册类型并自动保存。
- 常驻“命令输入”由父工作台负责。每次提示使用独立的 `job_id + prompt_id`，第二次、第三次相同文案的输入也会自动弹出。收起当前提示后可以手动重开；新提示仍会自动出现。任务结束或其他客户端已回答时关闭过期输入框。
- 常驻“收工归零并失能”先弹出目标串口确认，再在独立进程中读取位置、检查模式、按受限速度分阶段归零。确认到位、失能反馈后释放串口；失败不会假报成功。收工归零不改写校准零点。
- “设备连接与校准”增加从臂零点调整，支持单臂/双臂、单关节/全臂。读取角度不会改零点；释放力矩与写入零点均要求二次确认。设零要求全部失能，随后写入、保存参数并回读。全臂设零同步官方校准元数据并备份原文件。
- “视觉抓取”和“从臂控制”页面及前端脚本已删除，导航入口移除，旧地址跳转到总览。官方 URDF、STL、共享监视、底层工具保留。

## 模式确认故障

实际使用的 editable B601 插件位于项目目录之外。本次同时修复该安装源，并把可复用补丁保存为 `vendor_patches/b601_mode_readback.patch`。

写寄存器 10 的 ACK 丢失后，最多进行有界重试；只有实时读回目标模式，才接受模式切换。所有 DM 关节在使能前使用实测位置初始化目标。无反馈、回读不符或超时均阻止继续。部分连接失败及双臂回滚不再触发额外自动归零；校准 CLI 以失能状态进入手动校准，其他 `connect(calibrate=False)` 调用保持正常控制语义。

“gripper zero-detect … passed”不再触发错误的零点失败提示。任务输出读取由同一线程关闭管道，完成状态只发布一次，避免重复结束日志和关闭中的描述符竞争。

重新安装或升级硬件插件后，需要核对并重放补丁；升级时先检查上下文，不应盲目覆盖不同版本。补丁根路径是 `lerobot-robot-seeed-b601`，可先用 `patch --dry-run -p1` 检查。本机安装源已经应用，无需重复执行。

## 数据回放

每集所有录制相机独立呈现，共用时间轴、播放和暂停，播放时纠正明显的时间偏差。画面可放大，关闭后恢复原视频元素。缺失相机独立报错；跨数据文件的同一集轨迹合并读取。视频缓存区分相机、chunk、file、时间段和源文件版本，并以临时文件完成后原子替换，避免复用错误/半成品片段。

## 验证边界

使用模拟总线、临时数据集和拦截全部网络请求的浏览器检查；没有对真实机械臂执行归零、失能或设零验收。原有深度采集与抓取代码未修改；深度结合方案仅分析于 `DEPTH_CAMERA_ANALYSIS_20261114.md`。
