# 3.5.5 扫码与数据采集隔离

- 采集页、评估页下拉框提交设备源，保留 `0` 和 `/dev/v4l/` 稳定路径。已有名称形式的偏好会迁移到设备源；后端继续识别唯一的旧相机名称。名字不按设备路径解析，未找到时不会默认改扫全部相机。
- 物理取流仍只有共享视觉进程。扫码通过只读 JPEG 快照 RPC 取得缓存，不推进采集租约的读位置、不更改已有取流分辨率/帧率。设备任务运行时禁止扫码额外打开未取流的摄像头；无共享帧时返回未就绪状态。
- 条码解码、增强、白色面单检测、OCR 和预览绘框在独立、低优先级的识别进程运行。限制 OpenCV、ONNX 和 BLAS 的线程资源；支持的平台将其限制到一个可用 CPU 核。
- 同时只接受一个识别请求，忙碌时立即返回进行中状态，不排队。JPEG 传输和识别有合计超时；只回收识别进程，不关闭共享相机或停止采集，下次扫码可恢复。
- 状态锁不覆盖取帧、进程通信或识别等待。采集页 `save:false` 继续只显示结果，不保存单号；评估页按原功能保存并提供下载。
- 任务运行时只看“采集/评估时自动扫码”开关；“待机也扫码”不再绕过前一个开关。后台识别失败会显示状态，不只在手动扫码时提示。

自动化验证使用模拟相机、真实生成二维码和独立识别子进程，覆盖名称/设备源选择、数字 0、重复/移除相机、单消费者读位置隔离、保持分辨率、识别超时恢复、忙碌不排队和不持有任务锁。没有对机械臂发送测试动作。

「相机设备 → 全部预览」会在明确点击后恢复已暂停的共享视觉会话，启动全部已配置相机的预览。相机页主动确保常驻画面已启动，直接复用同一共享图像，不为本页重新采集。首次画面已收到但 MJPEG 尚未触发 `load` 时，也会标记可显示；无帧时展示共享连接状态，不再无限显示没有原因的首帧等待。重复点击不会另开同一设备的取流请求。浏览器测试模拟三路画面、全局暂停和缺少 `load` 事件，验证恢复、镜像显示和请求数量。
