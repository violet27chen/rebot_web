# 3.5.2：从臂端口与模型绑定

实时监视以「设备连接与校准」中保存的从臂端口为准：双臂分别读取 `dual_arm.left.follower_port`、`dual_arm.right.follower_port`；单臂读取 `follower.port`。不根据 `ttyACM` 编号大小猜测左右，也不自动交换用户的端口配置。

- 后端将稳定串口路径解析到实际设备，以当前配置重新分配反馈的左右归属，不信任旧进程缓存的左右标签。
- 前端同样按实际端口匹配模型。每个官方模型基座旁显示左右与实际串口；稳定路径保留在提示信息中。
- 切换模式、交换端口或稳定路径指向发生变化时，清除旧姿态并等待新反馈；旧绑定、乱序数据不会覆盖新姿态。
- 左右配置指向同一设备时不任意分配反馈。无反馈或反馈超时会显示等待或过期状态；清除姿态只是显示操作，不会发出机械臂运动指令。
- 沿用官方 URDF/STL，两套模型关节实例独立，放大时模型旁的端口标签一起显示。
- 训练不占用机械臂串口，可保留空闲只读反馈；遥操作、采集、校准等硬件任务拥有串口期间退出空闲观察器。

离线验证：`tests/test_telemetry_bindings.py` 覆盖端口交换、旧标签、稳定路径、单臂使用原右臂端口、重复设备别名、旧反馈与任务串口互斥；`tests/browser/model-port-mapping.cjs` 使用实际官方模型加载器和资源验证两个模型的姿态与端口标签，所有设备接口均为模拟。

前端静态资源已更新缓存版本。后端进程需要在当前训练任务结束后重启，才能加载后端绑定校验；本次没有为部署修复而中断训练，也没有执行机械臂动作。
