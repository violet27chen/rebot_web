# 通知到期与采集启动状态 · 3.5.9

右下角普通/成功/提示通知独立显示 5 秒，错误通知独立显示 12 秒。新通知不重置已有通知；鼠标悬停、焦点停留不暂停到期。子页面把通知交给常驻外壳创建，因此切换 iframe 页面不会留下失去定时器的通知。手动关闭和最多四条的显示限制保留，被移出列表时同时清理定时器。需要明确确认的模态框不受通知到期机制影响。

采集还没有输出过 Recording episode 时，Stop recording / 清理设备不能显示为“已完成”。后台进度携带 has_started、startup_error，页面显示“未开始采集”“启动失败 / 未完成，正在清理设备”，进度条保持 0%。开始保存时显示“保存中”，成功退出后才可认定任务完成。

状态 API 新增 last_job，供没有先收到 WebSocket 结束事件的页面读取真实退出码。空闲或 null 退出码不能推断为成功。失败提示不会被随后轮询的 700ms 自动反馈再次改成“完成”。

Leader 驱动检查有界重试，每个已配置 ID 最多 ping 四次，报告端口、波特率、已响应和缺失 ID。连接使用完整实测角度初始化缓存，不用零值代替。双主臂任一侧连接失败会释放已经打开的另一侧，避免只检查组合 is_connected 而遗漏左侧串口。录制先连接主臂，通过后才连接从臂；无法通信不会通过跳过 ID 检查伪装成功。

对应安装环境的源码补丁可重放：

```bash
python scripts/apply_leader_startup.py
```

脚本只检查和修改本地源码，不打开设备；不兼容源码在 dry-run 阶段报错。软件重试无法修复断电、错误串口、未接通的舵机总线等物理问题。

验证包含虚拟浏览器时间推进、通知交错到期、悬停/焦点、子页面导航、确认框保持；模拟总线验证主臂重试、失败回滚、初始角度以及录制连接顺序。实机只执行过 Leader ping 诊断，没有发送位置、力矩、设零、解锁或归零命令。
