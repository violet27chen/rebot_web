# 3.5.15：SmolVLA Action Chunk、Flow Matching 与 Async

SmolVLA 原本就通过 Flow Matching 生成动作块。本版接通原生采样参数和动作执行长度，继续使用独立推理进程与共享内存观察输入；没有另写生成网络、修改模型权重或改变训练算法。

## 评估配置

- `async_chunk_size`：每块执行步数，0沿用检查点；显式正数同时约束在检查点 `chunk_size` 和 `n_action_steps` 内。同步、异步评估均使用原生 `n_action_steps` 覆盖。
- `flow_matching_steps`：0沿用检查点，1–50覆盖 SmolVLA 原生 `num_steps`。同步、异步均生效；ACT不接受正数。该值是一次生成的采样迭代次数，不是动作块长度，也不是训练步数。减少迭代可能损失动作质量。
- Async：加载及预热在独立进程完成；缓冲区执行期间提前生成下一块。块之间不会因为本调度器自动收工、回零或失能。模型从示教学到的回收动作仍可能输出。
- 子进程就绪后发出 `REBOT_INFERENCE_READY`，状态接口与评估页面显示实际类型、执行步数、模型块长度及采样次数。界面填0时实际显示检查点值。
- 当前 `tese5/002000` 检查点的原始值为50步动作、50步执行、10次 Flow Matching 迭代。建议先保留两个0并启用Async，再根据效果测量调整。

独立 `sorting_operator` 目录已同步运行库；`sorting.json` 的 `inference.chunk_size` 和 `inference.flow_matching_steps` 使用相同约定，`--check-async` 与正式运行共用配置。随包原ACT权重未替换为SmolVLA。

## 肘关节 +6.27° 越界停止修复

旧异步层将模型目标越界与实测反馈越界合并，因预测左肘+6.27°超过[-200°,0°]上限而立即停止；驱动本身原有目标限幅尚未得到执行机会。现在先区分两者，再在电机空间投影目标到原有物理范围，之后才进行逐帧及反馈领先限速。

- 实测反馈越界超过5°仍停止；模型原始目标越界超过30°仍停止，物理限位未扩大。
- 可投影的目标先限幅，再按既有单帧2°、领先实测6°推进；实际失跟超过30°、非有限值和反馈缺失保护仍保留。
- 连续2秒预测越界超过5°会停止并报告持续越界，避免无限掩盖模型不适配。
- 日志保留原始目标、限幅目标与关节名。此处理不能证明模型学会快递分拣，也不替代正确标定与模型验证。

## 验证范围

回归测试包含原始肘关节报错、方向与夹爪倍率换算、严重越界与反馈异常拦截、持续投影停止、同步/异步参数传递、实际就绪状态、独立执行器参数。

真实GPU测试使用当前SmolVLA权重和all_1录制的三路RGB，反馈来自虚拟跟随器。设置5次采样、50步动作执行、seed=7，5秒运行返回145帧，首预测后等待帧0，过期块0；首预测约167ms，控制调用最长约3.53ms，最大逐帧变化约2°、最大领先约6°。5次采样仅用于确认参数传递和管线工作，默认生产配置仍沿用检查点10次。这不是实机分拣成功率或实时控制保证。

日志：`/tmp/rebot-smolvla-flow5-async.log`。没有打开串口、CAN或摄像头，没有启动真机评估，也没有修改零点、方向、增益或力矩阈值。
