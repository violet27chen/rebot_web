# 3.5.6 · ACT 提前推理与采集保存

## ACT 执行

在「快递分拣 / 策略评估」启用 ACT 异步推理。独立 spawn 进程加载检查点及原预处理、反归一化参数，先预热再连接机械臂。机器人进程负责读取反馈、发送动作和既有停止收尾。观测通过共享内存传递，管道只发送请求元信息和小型动作数组。

默认每次取最多 50 步，剩余 60% 时提前预测，并结合实测推理延迟增加提前量。结果按控制时间对齐，丢弃已执行部分；重叠位置用 5 步权重过渡。每集使用独立代次，旧集的预测不能进入新集。两段动作之间不会调用断连、回零或失能。

启动或缓冲暂时为空时保持上一有效命令；第一次保持命令来自真实电机反馈，使用方向和夹爪减速比的逆映射。缺失反馈不能用零值代替。预测年龄默认上限 1.5s，等待超时默认 2s；无效、过期持续缺货或超时会请求正常停止并按现有结束回零配置收尾。单帧变化默认最多 2°（电机角度），预测偏离实测超过 30°拒绝。原驱动的温度、关节限位等检查继续执行。这些限制不能代替碰撞规划。

日志每 2s 显示预测延迟、可用动作和过期块数量。等待预测时不累计「连续静止自动结束」时间；关节静止不代表视觉确认包裹清空。检查点开启内部 temporal ensemble 时需关闭此异步选项，防止重复集成。

固定多集评估的重置等待使用有期限的保持循环，避免原生无策略、无主臂时跳过计时而无限空转。异步预测不能消除示教中已经学入模型的停顿或回零动作，也不等于多个技能模型的切换器。

## 采集保存

原生 LeRobot 先写 PNG，再在每集结束等待图片写盘、统计和编码。三路 1080p、30 FPS 会产生较多临时图片；默认 AV1 编码可能增加剧集切换等待。这里没有「扫码成功后才允许下一集」的条件。

新数据集默认录制 640×360、H.264，每路两个写盘线程；可在「训练数据 → 采集画质与保存速度」自动保存为 1280×720 或设备原始尺寸。三路相机全部保留。输出缩放在共享视觉进程完成，不改变物理相机配置，因此监视和扫码仍可使用高清源画面。

续录读取原 meta/info.json，保留原尺寸、帧率和编码；不能向旧 AV1 视频拼入 H.264。旧 AV1 数据集续录仍可能较慢。评估相机输出尺寸遵从检查点特征，以兼容已有模型。

保存包装调用原生 save_episode，顺序编码避免从多线程机器人进程 fork 编码子进程；仍按每集编码，不通过积攒多集 PNG 掩盖等待。每 2s 输出实际保存阶段与经过时间，前端展示这些日志。重置、保存时暂停该采集页的自动扫码，下一集真实开始后恢复；手动扫码保留独立进程和有界等待。页面也可能在后台不可见时停止自动扫码。

数据集列表将视频、临时图片的占用分别显示。不会自动删除、重编码旧数据，也不会自动清理中断录制留下的临时帧。实际体积取决于场景、集长和压缩结果，不能由「三集」单独判断。

## 验证范围

- 模拟电机反馈验证方向/夹爪比例、过期和跨集拒绝、衔接、限幅、等待超时。
- 延迟模拟推理进程验证提前推理期间控制调用不会同步等待计算，并在退出时清理共享内存。
- 安装环境中的真实三相机 ACT 检查点在 CPU 子进程加载、预热并返回有限动作。
- 原生 LeRobot 连续保存两集三相机 H.264，逐路解码检查尺寸和帧数、无遗留 PNG。
- 浏览器隔离测试检查画质/异步参数自动保存、保存期间暂停扫码及下一集恢复；所有设备 API 被模拟。
- 未执行真机机械臂动作测试。
