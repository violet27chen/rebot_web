# 采集倒计时修复 · 3.5.8

原页面会把心跳日志中的「最近输出：Recording episode … / Reset the environment」重复当作新阶段，每次重置起始时间。本地倒计时归零又提前进入重置阶段，真实重置日志到达后再次起算；开始请求的 HTTP 响应晚于 WebSocket 时也会把已经开始的弹窗初始化。

现在后台按当前录制子进程的实际输出维护阶段与递增序号。单集时间、重置时间、剧集数和数据集名来自本次已启动命令的参数快照。状态 API 和 WebSocket 都携带相同阶段、序号及按 monotonic 时钟计算的 elapsed_s。重复开始/重置/保存日志不会改变阶段时间；明确重录才允许同一剧集重新起算。续录从本次实际起始剧集索引换算界面集数。

页面使用 performance.now 续算；同一阶段只校正为更大的已用时，丢弃旧阶段。渲染不驱动阶段切换，倒计时归零后显示等待录制进程切换。手动按键只表示请求已发送，不提前改变实际倒计时。任务 ID 绑定防止迟到的开始响应重置计时、旧任务结束关闭新任务弹窗。

切回页面或刷新时从当前状态恢复。保存阶段继续显示尚余集数和录制/重置时间估算，保存耗时单独等待，不再提前把总剩余显示为零。重置时长为 0 不再被当成默认 10 秒。

只修改进度解析和展示，不改变采集时长、控制循环、归零或失能路径。旧后台尚未重启时，页面保留去重后的日志兼容模式；新版本状态恢复需后台更新生效。

验证包含实际 stdout 解析、重复心跳、阶段等待、重录、续录索引、零重置时长、状态 API、页面刷新、HTTP/WebSocket 先后顺序和旧任务事件。浏览器测试全部拦截设备 API，未执行真机运动或启动真实采集。
