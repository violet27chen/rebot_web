# 异步ACT独立启动与跟随误差 · 3.5.13

用户20:37日志的实际原因：right_shoulder_lift.pos 绝对目标 -35.40°，实测 -3.86°，原检查在限速前判定31.54°超过30°并停止。推理已经完成，不是ACT进程没有返回。收工结束时的汇总 RuntimeError 没有保留此原因，增加了定位难度。

修复顺序为：检查预测和反馈的有效性、物理限位；在电机角度空间对每帧目标限速；最后检查实际待发送命令对实测角度的偏差。按该日志每帧最多2°，本帧只允许到 -5.86°，不会直接下发 -35.40°。30°跟随误差保护继续适用于所有关节，夹爪不再需要放宽跟随阈值到完整行程。机械臂未跟随而命令逐帧累积时仍会拒绝；故障本帧按实测位置保持，随后执行既有清理。

独立目录还有一个实际启动缺陷：PreTrainedConfig.from_pretrained 在全新解释器里没有预先注册ACT选择类。原单元测试先导入了ACTConfig而掩盖该错误。现在主入口显式注册并验证ACT配置，新增全新解释器启动测试。

Actor的预处理器device覆盖与本次推理设备保持一致，避免CUDA保存的归一化/预处理配置在CPU诊断时造成设备不匹配。推理子进程退出时先读取其已发送错误，汇总异常保留具体 failure_reason；执行台提供PID、缓冲步数、等待状态和原因。

新增无硬件自检：

```bash
python sorting_operator/run_sorting.py --check-async --device cuda --seconds 5
```

该自检不导入电机控制、不打开相机、不执行运动，用随包真实tese1/020000模型、三路360×640内存画面和虚拟状态验证共享内存、推理和缓冲。它不检验包裹操作能力，也不绕过实际执行路径的安全校验；报告 safety_gates_exercised=false 明确区分此范围。

本机RTX 5090 Laptop测试：5秒、8块、149个可用预测帧、首帧后0等待帧、0过期块；首帧约34ms，最长控制端poll约1.81ms，最长观测到的推理响应约33.51ms。CPU自检也可运行，但当前模型在CPU上约1秒延迟，存在缓冲等待，不能据此期待30Hz连续执行。上述为本次空闲环境测量，非所有负载下的时延保证。

234项无硬件回归测试通过。修复同时同步到 backend 与 sorting_operator/rebot_sort_support；随包模型权重未改变，没有重置校准或驱动电机。已运行的进程不会热替换已导入模块，应正常结束后重新启动任务/入口；不要在运动中为更新代码强杀进程。
